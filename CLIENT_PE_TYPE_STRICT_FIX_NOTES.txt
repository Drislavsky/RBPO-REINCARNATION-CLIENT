Client-only fix: strict object type detection for PE vs SCRIPT.

Changes in src/service.cpp:
- PE files are now detected only when BOTH conditions are true:
  1) extension is .exe, .dll, .sys, or .scr
  2) file bytes start with MZ
- Script/text extensions win even if file content starts with MZ:
  .js, .py, .ps1, .bat, .cmd, .vbs, .wsf, .hta, .script, .txt
- The scan engine now requires exact ObjectType match before checking offsets/hash.
  This prevents PE signatures from being detected in .txt/.bat/.script files.
- Server code was not changed.

Expected tests:
- PE signature + pe-good.exe starting with MZ => INFECTED
- Same PE signature inside pe-in-txt.txt => CLEAN
- SCRIPT signature inside .bat/.cmd/.script/.txt => INFECTED
